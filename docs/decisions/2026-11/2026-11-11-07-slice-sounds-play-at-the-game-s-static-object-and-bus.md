## 2026-11-11: Slice sounds play at the game's static object and bus volumes; 2D mono goes out as two equal channels (audio mix lane)

AI-assisted (Claude Opus 5.5). Record: `docs/verification/SLICE_AUDIO_CHAIN.md` section 7.

- **Cause of "only the shots".** The decoded files are not balanced against each other: equip is well under the shot in RMS in the files themselves (the file levels are read from the install and stay local). On top of that, the host played a mono 2D sound 6 dB lower than a stereo one (a fit of the 2026-11-10 recording against the source files: -9.0 dB against -3.0 dB). The game's own balance comes from its Wwise mix, which the host did not apply.
- **What changed.** `tools/prepare_slice_audio.py --game` reads the installed banks with `tools/audio_census.py`'s readers. For each played file it sums the volumes (property id 0) on the sound, its containers and actor-mixers, and its bus chain. A weapon switch container picks the first-person child for the player's own roles; two play actions on one source add as amplitudes. The result goes into `audio_play.json` as `gains` (per file) and `gain_notes`. `OpenWillowAudio` spawns each file at its gain and sends a 2D mono file as two equal channels. `tools/listen_report.py` adds a per-role level table against that prediction, balanced against the shot.
- **Values (this install).** One level per file and role, read from the install; they are in the ignored `local/slice/audio_play.json` (`gains`) that `prepare_slice_audio.py --game` writes.
- **Verified.** The layouts hold over the whole install by structural oracles: 143,478 of 144,568 sound parents resolve at a fixed offset; all 25,034 containers without effects have a resolving parent or bus; 994 of 995 switch value lists name only the container's children. FNV-1 of `firstperson` and `thirdperson` match the weapon switch's two values. Python tests (synthetic): prepare 52/52, listen report 27/27.
