## 2026-11-11: Slice-npc and Phaselock-target jobs store repo-relative paths; the provisioner can refresh stale files; editor launchers check their checkout (lane-data-hygiene)

AI-assisted (Claude Opus 5.5). Tool behaviour change in `tools/slice_npc_assets.py`, `tools/prepare_phaselock_target.py`, the new `tools/repo_paths.py` and `tools/checkout_guard.ps1`, `tools/provision_worktree_assets.ps1`, `tools/import_phaselock_target.ps1` and `tools/seed_slice_npc_assets.ps1`. No parser, host or dependency change.

- **Why.** The in-engine run of 2026-11-10 was invalid for reasons outside the code under test. A worktree's Content held an `M_OW_NPC_Zone` older than its newer scalar parameters, and the provisioner never replaces a file that exists. The slice-npc job held absolute paths; copied between worktrees, they pointed into a deleted worktree and the target dummy's zone step found nothing. One editor report was also written into another worktree. The audit could not reproduce that from main's code and guessed that another worktree's copy of the script was run from a different directory (still a guess).
- **Paths.** `editor_job.json` from both tools, the UModel inventory's output paths and the Phaselock identity's `props` paths are written relative to the repository root. The two launchers turn the stored job into `editor_job.resolved.json` for their own checkout (`python tools/repo_paths.py resolve-job`) and point `OPENWILLOW_SLICE_JOB` at it, so the editor scripts (`tools/slice_npc_editor.py`, `tools/phaselock_target_editor.py`, the attach step) still read absolute paths and are unchanged. An old job with absolute paths still works: a path inside this checkout is kept; outside it, an input that exists is used, and a missing input or any output (the report folder, the reference pose) stops the launcher with the job file, the path and the command that rewrites the job. The provisioner never copies the resolved file.
- **Refresh.** `-RefreshStale` on the provisioner also replaces an existing file when the source's copy is newer and differs (size, then SHA-256 if the sizes match), in every mode, and prints each replaced path with a per-folder count. A worktree copy that is newer than the source is kept. Without the switch nothing changes: existing files are never overwritten.
- **Guard.** Both launchers dot-source `tools/checkout_guard.ps1`. It prints `Repository root: <root>` and throws when the current directory is inside a different checkout of this repository (the nearest folder upwards with a `.git` entry that also holds `host/ue5/OpenWillow/OpenWillow.uproject`). A directory outside any checkout is allowed.
- **PR #186.** It shows as closed, but it was not rejected. It landed on main as 8ebab63 and GitHub shows it closed because the batch script moved the branch and main in one push. It resolved command-line paths of `tools/prepare_range.py` against the repository; this entry is about paths stored in job files and about stale seeded files, which #186 did not touch.
- **Verified (automated):** `tests/editor_inputs_test.py` (round trip through the repository root, a job copied into another worktree resolving there, an old absolute job present and missing, an output in another checkout refused, the guard's refusal and its two allowed cases), `tests/provision_worktree_test.py` (default keeps the stale file; the switch replaces it, names it and leaves a newer worktree copy and an identical older file alone; the resolved job is never copied).
- **Not verified:** no editor run. That `-Steps zone` in a worktree whose job was written by the new code reads the resolved job and writes its report into that worktree is UNVERIFIED until the runner's check.
