## 2026-11-11: `tools/play_slice.ps1` starts the whole slice for hand play, with no test driver (play-slice lane)

AI-assisted (Claude Opus 5.5). A new launcher and its test; no host code, parser, dependency or licence change.

- **Why.** No launcher could start the loop a person plays. `tools/run_quest.ps1` had the mission but no enemies, no sounds and no skills page, so from a fresh save Phaselock could not be bought (`AOpenWillowMayaHUD::OpenStatusMenu` returns while the skills URL is empty). `tools/play_range.ps1` had enemies but no mission and no Phaselock data. `tools/run_ue_flash_hud.ps1` served the pages but took everything else through `-Extra`.
- **What it does.** It composes what those three pass: the quest manifests and `-owquest`, `-owrangestart` with the range manifest (normal mode), `-owactionskill`, `-owaudioplay`, and `-owflashhud`, `-owflashskills` and `-owflashinventory` on one `serve.py` port (the host derives the missions, map and mission-screen URLs from the skills URL). It reuses `Start-OwMovieHud`, `Stop-OwMovieHud` and `Test-OwMovieHudLog` from `tools/movie_hud.ps1`, the process helpers of `tools/run_limit.ps1`, the range preflight of `tools/check_range.py` and `tools/check_overlay_data.py`. It holds the machine-wide UE run lock. The line carries no `-owslicegate*`, `-owcombattest`, `ow.Range*` command, granted point or forced damage. The start shield is the host's default, so no switch is needed for it.
- **Refusals.** Nine local files (the quest manifests, the slice gear, Phaselock data, the audio play map, the range manifest, the stand-in shield rule) and the converted HUD and status-page movies are checked before anything starts. Every missing one is named with the tool that makes it, and the script exits 2.
- **Smoke.** `-CheckSeconds N` runs N seconds with a fresh save of its own, stops only the editor it started, and grades the log: one PASS/FAIL line each for the mission (`OWQUEST READY`), the range (`OWRANGE start switch: built=1`), Phaselock's data, the audio play map (`OWAUDIO role=... files=N`, N > 0), the start shield (a capacity line), and the HUD, inventory, skills, missions and mission-screen pages' ready lines. Each pattern is a line the host or a page writes; the test checks that they are still in the source. Exit 1 on any FAIL.
- **Range and mission together.** In the host code, no rule keeps the range and the mission apart. The range subsystem never reads `-owquest`, and the quest counts only its own dummy. One gate log puts the range spot about 14,000 uu from Marcus's stock pose. The gate clears the range before the mission (`ow.RangeClear`, a fixture), so whether range enemies follow Maya to the mission, or get in its way, has never been run. No host change was made.
