## 2026-11-09: Mission lines and Marcus's barks play through the VM's line player (slice audio lane, dialog)

AI-assisted (Claude Opus 5.5). The listening guide listed Marcus's lines as "decoded, not hooked". The VM already runs the stock dialog and reports every line it chooses (event tag, talk act, talker, priority), and it has a line player interface (`DialogSystem::setLinePlayer` / `lineEnded`) that only the core's `lines:<s>` test length used. With `-owaudioplay`, `UOpenWillowQuest` now sets a timed line player (new in `src/dialog.*`, `setTimedLinePlayer`): it plays the play map's `line:<event tag>` through `OpenWillowAudio::Play` (which now gives back the chosen file's length) and returns that length, and the dialog's own clock ends the line at its exact time. So a line holds the next behavior as it did live without the dialog skipper (lane L4). `tools/prepare_slice_audio.py` maps one `line:` role per manifest `dialog:` / `marcus_group:` key (keys only, `dialog:` first, a missing file stays unresolved). The listening report describes line cues and drops "Marcus's lines" from the not-played list. Record: `docs/verification/SLICE_AUDIO_CHAIN.md` section 5c.
