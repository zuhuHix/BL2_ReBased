## 2026-11-08: Every real-game run writes a pending record before it changes anything, and lets go of every key (real-game harness)

AI-assisted (Claude Opus 5.5). Docs: `docs/TOOLING.md`, "Pending records and guarded input".

- **Change:** the showcase capture's crash safety is now the harness's (`tools/real_game/pending.ps1`). A run writes a record under `%LOCALAPPDATA%\OpenWillow\` (script, PID, start time, backup, each root's tree hash, what it changed) before the driver's save block, the launch or SDK mods off, and removes it only after the restore is verified by tree hash. Every one of the 18 scripts under `tools/real_game/` refuses to start while any record is left, printing the steps. The shorter captures (HUD, walking, generator confirm, weapon part session) now restore every root from a verified backup and keep both locks when it does not compare clean; before, some left added files in place, one compared the wrong folder and one only listed differences. `Backup-Saves` now proves its copy by hash.
- **Input:** every press is tracked and released in each run's `finally` (`Release-HeldInputs`); presses held across steps got their own `try`/`finally`.
- **Choice:** at start a record is completed by itself only when nothing has to be rolled back, or when the only leftover is this driver's untouched copy. Restoring saves by itself could erase play since the crash, so that needs `Restore-PendingRecord`.
- **Not changed:** the ignored showcase script keeps its own records and checks; the harness honours them.
- **Review (PR #184 r1), fail closed:** the writer of a record is identified by PID and UTC process start time, not by its command line; a writer alive, or one that cannot be shown gone, is never completed automatically (`Restore-PendingRecord -WriterGone` is the person's override for the second). `OW_TEST_PENDING_DIR` is honoured only together with `OW_TEST_MODE=synthetic-real-game` and only on save, game and driver folders under Temp; otherwise the harness refuses to start. `Restore-PendingRecord` first copies the current roots to a pre-restore folder and verifies it by tree hash. `Install-Driver` is always exclusive (a claimed folder via `-ClaimedBy`), and `Remove-Driver` removes only what this process installed. Tree hashes and comparisons use ordinal, case-sensitive paths, and the harness hashes with .NET instead of `Get-FileHash`. The seven barred scripts stay barred until a granted smoke run passes. **Review r2:** while a record exists only `Restore-PendingRecord` is printed or allowed (`Restore-VerifiedBackup` refuses, and otherwise also copies the current state aside first); every launch backs up, records and restores `sdk_mods/settings` and `sdk_mods/SanitySaver` too; every restore entry point checks the test-mode roots, including paths read from the backup manifest; recovery holds the run lock and checks for a running game at each step; the driver owner id is stored in `.owrun` and the record and must match exactly; held keys are written into the record and released by the next run or the recovery while a game window exists (a killed run with the game open can leave a key held until then). **Review r3:** a record whose backup manifest lacks any of SaveData, Config, sdk_settings, SanitySaver is never completed automatically (Restore-PendingRecord restores what it covers, names the rest as not vouched for and leaves `recovery_note.txt`); a game seen after a restore keeps the record and names the pre-restore copy (nothing locks the game out: don't start it during recovery); held keys are cleared only when no game process runs at all.
- **Checked:** synthetic tests only (`tests/real_game_pending_test.py`, 27, plus the existing capture tests). No real-game run yet: a real run would show whether the record, restore and release hold up around the real game.
