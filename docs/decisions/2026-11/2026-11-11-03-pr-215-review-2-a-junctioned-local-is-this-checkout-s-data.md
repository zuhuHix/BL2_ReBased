- **Junction rule (hub, written into `tools/worktree-assets.md`).** (a) The real location of `<root>/local` is this checkout's data root wherever it resolves, also when that is another checkout's `local/`, so paths under it are ours. (b) Any other path that resolves into another checkout is refused. (c) A junction or symlink on the way whose target is gone is refused. (d) Files and folders not written yet, below the deepest existing folder, are fine. Round 1 refused every path of a worktree whose `local/` is a junction to the main checkout's (against (a)). It also accepted a path through a junction once the checkout it pointed into was deleted (against (c)). Both are fixed. Under (d) missing folders below the deepest existing one are allowed as well as a missing leaf, because nothing that does not exist can redirect a path.
- **Refresh backups.** Backups now go to the worktree's own git directory (`<git dir>/ow-refresh/<UTC time with milliseconds>-<process id>/<path>`, next to the provisioning marker). They no longer go under `local/`, so a worktree with a junctioned `local/` can refresh stale Content. A backup folder that already exists is refused in the preflight. So is a backup path of 260 characters or more: a real linked worktree here first failed that way with a raw .NET error, and nothing was written. Seed mode is unchanged (`<seed>/worktree-refresh-backup/...`).
