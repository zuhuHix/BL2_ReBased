# Legal policy and clean-room rules

This page states, in one place, what OpenWillow is and is not, what the
repository contains, and the rules every contributor and every AI assistant
works under. It is project policy, not legal advice.

## Non-affiliation

OpenWillow is an independent, non-commercial, fan-made engine project.
Borderlands, Borderlands 2, Gearbox, and related names and marks are
trademarks of their respective owners. OpenWillow is not affiliated with,
endorsed by, sponsored by, or supported by Gearbox Software, 2K Games, or
Take-Two Interactive. The name "OpenWillow" refers to the engine branch's
internal codename and is used descriptively.

## What this repository contains

- Original C++ and Python source for a package reader, asset importers, level
  preparation tools, and a minimal Unreal Engine 5 host project.
- Synthetic test fixtures, generated by the tests themselves, containing no
  game data.
- Planning, research and verification documents.
- A research corpus of public Steam review text and forum/search snippets,
  collected via public APIs and re-runnable scripts (see
  [`research/README.md`](../research/README.md)).
- One vendored third-party library (lzokay, MIT) with recorded provenance.

## What this repository does not contain, and never will

- Any file from a Borderlands 2 installation: no packages (`.upk`, `.umap`,
  `.u`), texture caches (`.tfc`), audio banks (`.pck`), video (`.bik`), UI
  movies (`.gfx`, `.swf`), shader caches, or configuration files.
- Any decompressed, extracted, converted or derived copy of the above:
  no texture dumps, mesh exports, level manifests, property dumps or
  screenshots of loaded game content. All such outputs are written to
  git-ignored directories (`local/`, UE `Saved/`) on the contributor's
  machine only.
- Any Gearbox, 2K, Take-Two or Epic Games source code, leaked or otherwise.
- Any code transcribed from disassembling or decompiling `Borderlands2.exe`
  or any other shipped binary.

A pre-write hook in [`.claude/hooks/sensitive_guard.py`](../.claude/hooks/sensitive_guard.py)
refuses to write game-file extensions into the tree, and `.gitignore`
excludes every output directory the tools use.

## Runtime requirement

The engine reads the player's own installed copy of Borderlands 2 at runtime
and refuses to start without one. It does not modify the installation. There
is no plan, ever, to make the engine work without the original game.

## Clean-room rules

1. **Never redistribute a Gearbox file.** See above.
2. **Never use, read, or accept leaked source code.** Not Unreal Engine 3's,
   not Gearbox's. If it is offered, the answer is no, in writing.
3. **No decompiled executable code.** Observing the behaviour of the running
   game — including hooking its functions with tools such as unrealsdk and
   logging inputs and outputs — is how we build golden files. Disassembling the
   executable and transcribing what it does is not permitted.
4. **Formats may be referenced; code may not be copied without a decision.**
   Reading a public reference implementation (UE Viewer, Legendary Explorer,
   UDK's shipped `.uc` headers) to learn a serialization order is permitted
   and must be recorded in [THIRD_PARTY.md](../THIRD_PARTY.md) with the source
   and its license. Copying or translating code from such a project is a
   license decision made by the maintainer, never by a contributor or an AI
   assistant on their own.
5. **Never sell anything.** No paid builds, no premium features, no early
   access tiers. If donations are ever accepted they support engine
   development only.
6. **Require the original game.** See above.
7. **Disclose AI assistance and keep verification claims honest.** Automated
   checks are reported separately from in-game checks. Behaviour that has
   not been verified against the real game is labelled `UNVERIFIED`.

These are the rules that OpenMW, OpenRCT2, Daggerfall Unity, OpenGothic and
Ship of Harkinian have operated under. We follow the precedent deliberately.

## Contributor certification

By opening a pull request you certify that:

- the contribution is your own original work or is properly attributed
  under a license recorded in `THIRD_PARTY.md`;
- you have not consulted leaked source code or decompiled executable code
  in producing it;
- it contains no game files or game-derived data;
- any format claim it relies on states how it was observed.

## Issues and reports

Screenshots of the OpenWillow viewer or of the original game are welcome in
issues for comparison — that is the plan's verification method. Attaching
package files, extracted textures, meshes, dumps or logs that embed raw asset
bytes is not; such attachments will be removed.

## License status

A project-wide open-source license has **not yet been selected.** Until it
is, all rights in the original code and documents are reserved by the author.
The repository is public for transparency and so that the work can be
verified; it is not yet licensed for reuse. The candidates under
consideration are MIT and GPL-3. The choice is gated on a provenance review
of the Python research decompressor described in
[THIRD_PARTY.md](../THIRD_PARTY.md). Vendored third-party code retains its own
license (lzokay: MIT, in `third_party/lzokay/LICENSE`).

Because contributions cannot be relicensed after the fact without every
contributor's consent, **external code contributions are not merged until the
license is chosen.** Issue reports, verification results and format findings
are welcome now and are not subject to this restriction.

## Contact for rights holders

If you represent a rights holder and believe this project infringes your
rights, please open an issue or contact the repository owner directly through
the contact details on their GitHub profile. We will respond promptly and in
good faith.
